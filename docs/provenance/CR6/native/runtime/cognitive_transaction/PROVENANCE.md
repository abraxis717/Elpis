# CR4-P2: exclusive cognitive enrollment reference coordinator

This isolated candidate composes the exact CR1/CR2/CR3 sealed implementations and qualified CR4-P1 checked binding. No sealed source is edited. The private owning translation units include the original geodome_state.c and cgc_pool.c verbatim instead of compiling them separately. They add internal image-copy helpers; the final root-build integration must review how those helpers are admitted without duplicate symbols or exposing them as public cloning APIs.

A runtime exclusively owns one immutable index, one volatile session, one existing double-buffered evidence store, and two preallocated physical/adaptive image pairs. The image pairs represent one logical identity, not two independent objects. Copy the committed image into the other image at begin; preserve owner/epoch/generation, all values and residency mappings, and all adaptive banks. No speculative locator or raw component pointer leaves the coordinator. A serialized trusted caller must use only this API; this is not concurrent publication or an in-process malicious-code boundary.

Only initial enrollment (physical row, initial adaptive banks, first evidence association) and additional association are implemented. Stage failures poison the active transaction; abort is mandatory. Foreign tokens refuse without poisoning the current transaction. All reads select the committed image and are coordinate-pinned; source authority transitions are allowed only while idle and use the unchanged session transition law. No adaptive learning, release, pruning, reset, transport or multi-turn budget authority is admitted here. Source invalidation can suspend/retire evidence without releasing the resident cells. Admission budget is per transaction, inherited from CR3; this is not an aggregate RuntimeCore turn limit.

Commit calls the existing fallible evidence publication last; refusal leaves the physical/adaptive live selector unchanged, evidence unchanged and output unchanged. Once evidence commit succeeds, only infallible local scalar/receipt publication remains, with no callback or external reader between these operations. The observable boundary is the exclusive serialized API call, not a hardware atomic write, crash recovery protocol or Rust RuntimeCore integration. Abort discards staged evidence and makes the shadow images inaccessible; they are overwritten at the next begin. No RAM erasure claim. Evidence IDs and strict current locator revisions remain unchanged; P3 must explicitly address adaptive revision updates and provenance.

Resource bound: one immutable index, two fixed-capacity physical/adaptive images, one evidence store, one session. Direct allocation counts exclude allocator internals and the Rust shared library; the actual session has its separate existing regression evidence. The reported component payload excludes the session, allocator overhead, stack and scheduler. Begin copies bounded image bytes; this is a correctness-first reference and no throughput advantage is claimed. No storage persistence, threads, model or GPU are introduced. Integrated containment is pending.
